# Existing report workflow review

This public retrospective records engineering and writing lessons from reviewing earlier reporting instructions and selected correspondence. Campaign identities, provider-specific private replies, message identifiers, personal information, and source artifacts are retained privately outside the repository.

## Preserve the useful boundaries

The former reporting skill and [archived routine](legacy-grok-routine.md) separated report composition from discovery and operational state. Preserve that division. The current [Provider abuse reporting guide](../../provider-abuse-reporting.md) replaces the former template.

Keep recipient-specific requests, exact resources in separately reviewed evidence, defanged authored bodies, accurate attachment descriptions, and clear distinctions between observation and inference. Following a section order is not a measure of report quality.

## General findings

| Failure pattern | Design consequence |
| --- | --- |
| A report lists a root domain while the relevant resource is a specific URL. | Give each recipient adequate evidence for the resource it controls. A report sent elsewhere does not supply evidence to this recipient. |
| A file described as full headers contains selected fields and analyst notes. | Label extracts accurately and separate original evidence from analysis. |
| DNS observations are presented as proof of served webpage content. | Require direct supporting evidence for each claim and mark unobserved content as unknown. |
| Authored links acquire redirect wrappers. | Compare prepared content with the stored outgoing representation and preserve exact source targets separately. |
| A recipient list includes an address controlled by the suspected attacker. | Verify recipients independently and enforce that boundary outside the prompt where possible. |
| Weak clues accumulate into an unsupported High assessment. | Require concrete deception or a malicious request and review contrary evidence. |
| Evidence files include recipient identifiers or private storage details. | Prepare a recipient-specific disclosure copy and keep local inventory separate from attachments. |
| A forward exposes more than its covering note suggests. | Review the complete outgoing payload, including quoted material and attachments. |

## Interpret outcomes narrowly

A provider-reported suspension is distinct from independently observed inactivity. A restriction on delivery to one recipient is distinct from a global account suspension. An unavailable resource does not by itself prove successful mitigation. Record outcome scope, evidence requests, and unresolved work separately.

A registrar response does not establish motive. Preserve original correspondence privately for any later escalation and distinguish its contents from public prevalence measurements.

## Improve the writing

Repeated confidence labels and duplicated summaries make reports longer without adding evidence. A report should identify the concrete concern and resource, provide decisive observations, and request an action the recipient can take. Put technical detail in accurately described attachments.

Correct unsupported claims themselves rather than adding a disclaimer after them. Do not impose a minimum word count or require repeated assessment paragraphs. Template compliance cannot replace a review of clarity and factual support.

The replacement guide excludes automatic forwarding to external analysis services. Original-message disclosure requires a specific purpose, a review of what it exposes, and operator approval. Every outgoing report requires approval in the first version.
