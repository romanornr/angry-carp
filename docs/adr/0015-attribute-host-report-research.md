# Attribute reporting research to the existing AI host

The operator selected Codex, Claude or Grok's existing host tools for reporting-time research, with attributed research records. Angry Carp starts a specific preparation and checks its returned research and draft. It does not add native search to Flue or require another search-provider credential. This implements the host-assisted form of ticket 18 and refines ADR 0013's previously deferred reporting stage.

The distinction matters because importing a record cannot establish that a fetch occurred or that a source is authoritative. Records say `host_supplied`. The command validates structure, references, declared chronology, source-host restrictions and exact byte bindings. The operator must inspect the host's trace, sources and actual draft wording. `ready_for_review` is not independent verification, disclosure approval or permission to send. A qualified investigation request can be supported even when provider custody remains unconfirmed.

A preparation binds one provider, service role, resource, reviewed destination, requested action and evidence copy to the existing private analysis. Only the reviewed request is disclosed to the host. The command hashes the analysis locally. It excludes hosts from action links and plain-text references, including quoted and embedded content, from research sources and report destinations. Those hosts remain private. A reported domain is a candidate automatically. The host follows the portable reporting guide, researches after preparation starts and returns three named checks for allegation, provider relationship and current channel. It preserves contrary and unresolved evidence. The checker holds contradicted, failed and unresolved checks.

Exact file digests bind preparation, analysis, research and draft versions. This borrows the subject-binding idea from the [in-toto Statement specification](https://github.com/in-toto/attestation/blob/main/spec/v1/statement.md), without adopting its attestation format, signatures or trust claims. Hashing retained bytes needs no JSON canonicalization; whitespace changes also change the binding. A changed target or destination requires a new preparation. Material draft changes need applicable research and every payload change needs new operator approval before a future send. The checker cannot determine semantic equivalence or authenticate a caller who rewrites every record.

Permitted research sources are explicit exact hostnames selected in the reviewed request. A source-authority label remains a claim. No arbitrary same-day or fixed-hour freshness threshold is introduced. Research happens for each preparation; applicability at final review is a human decision. Catalogue membership is a starting reference, not a prerequisite: current source evidence can establish a replacement route after the operator amends the request. This preserves channel updateability instead of treating a dated table as permanent authority.

`lib/` owns the schemas and checks; `cli/` owns bounded file access and explicit private outputs. There is no network call, model call, send operation, approval mechanism or automatic case creation in these commands. Repo-local files under ignored `evidence/` are explicit handoff artifacts. They do not replace the SQLite case-store decision in ADR 0006 or implement the report authority planned in ADR 0005. Users choose paths and retention; created files use exclusive mode 0600. Native research execution and durable approval/submission remain future work.

The trade-off is a usable, model-independent reporting workflow with weaker execution provenance than a trusted runtime executing retrieval itself. The operator accepted that boundary. [The command guide](../report-preparation.md) states its guarantees, schema and limitations. [Research](../research/remaining-assessment-and-reporting-work.md) distinguishes standards and software precedents from these project choices.
